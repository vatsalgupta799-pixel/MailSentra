## 4. Remaining Risks & Explicitly Deferred Scope

1. **Out-of-Scope Deferrals (Step 3.7.3C & Beyond):** `Authentication-Results` generation (`local_authserv_id`, `header.b`, header prepending), `ScanService` pipeline wiring, REST routes, DB-backed override rule CRUD tables, real SMTP socket execution, and upstream detection modules (Modules 5–8) were intentionally left unimplemented.
2. **Deferred Low-Severity Audit Observations (L1–L3):**
   - **`L1` (`dmarc.py`):** Under `psd=y` tree walks, an intermediate `psd=u` candidate below `child_org_domain` can still be selected if `child_org_domain` has no DMARC record.
   - **`L2` (`dmarc.py`, `dkim.py`):** Substring matching on `"missing original raw message bytes"` and offline PSL heuristic in standalone `DKIMVerifier` alignment.
   - **`L3` (`policy_enforcer.py`):** Caller-supplied `ForwarderTrustEvidence` objects lack an HTTP-channel block inside `_evaluate_indirect_flow_evidence()` unless callers restrict construction to verified MTA contexts.
3. **Subdomain Probe Default (`dmarc_enable_subdomain_existence_probe=False`):** Disabled by default to preserve compatibility with single-TXT offline test mocks; live email scan deployments enabling RFC 9989 §4.10.1 `np=` evaluation should configure `dmarc_enable_subdomain_existence_probe=True`.
4. **Offline Simulation Environment:** Verified via `MockDNSResolver` and in-memory SQLite (`sqlite+aiosqlite:///:memory:`), not live Internet DNS resolvers or PostgreSQL concurrency/isolation locks.
